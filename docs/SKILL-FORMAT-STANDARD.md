# SKILL.md 格式标准 v1.0

> 让 AI 更容易读懂、更准确地执行的技能写作规范。
> 适用于 acquisition-agent 全部 84+ 技能。
> 2026-04-22 制定

---

## 一、现状问题

| 问题 | 影响 | 出现频率 |
|------|------|---------|
| SKILL.md 超过 500 行 | AI 遗忘后半部分指令 | 11/85（13%） |
| Frontmatter 缺字段 | 触发不精准 | 9/85（11%） |
| 缺少快速参考卡 | AI 需要通读全文才能行动 | 大多数 |
| 指令散落在多个 reference 文件 | AI 不知道什么时候去读 | 部分复杂技能 |
| 没有明确"不做什么" | AI 做多余的事 | 常见 |
| 版本号缺失 | 无法追踪变更 | 6/85（7%） |

## 二、标准模板

### 完整结构（目标 ≤ 400 行）

```
---
name: skill-name
version: 1.0.0
description: "一句话说明做什么。包含触发场景关键词。MUST USE when..."
triggers:
  - 关键词1
  - 关键词2
---

# Skill 名称（与 name 一致）

## 一句话说明（3-5 句，告诉 AI 核心价值）

---

## 何时使用 / 何时不使用

### ✅ 使用场景
- 场景 1
- 场景 2

### ❌ 不使用场景
- 场景 A（应该用 skill-xxx）
- 场景 B（直接用工具就行）

---

## 核心流程（主逻辑）

用流程图或编号步骤，不用大段文字。

```
输入 → 步骤1 → 步骤2 → 步骤3 → 输出
```

### 关键规则（3-5 条）
1. 规则 1 — 为什么
2. 规则 2 — 为什么

---

## 输出格式

用代码块展示期望的输出结构，不要用自然语言描述。

```
## 报告标题
### 摘要
- 要点1
### 正文
```

---

## 输入要求

| 必需输入 | 说明 |
|---------|------|
| 输入1 | ... |

| 可选输入 | 说明 |
|---------|------|
| 输入2 | ... |

---

## 参考文档

| 文件 | 何时读取 | 内容 |
|------|---------|------|
| references/xxx.md | [触发条件] | 内容摘要 |

---

## 踩坑记录

| 日期 | 问题 | 修复 |
|------|------|------|
| YYYY-MM-DD | 描述 | 修复方案 |

---

_Version: 1.0.0 | 更新: YYYY-MM-DD_
```

## 三、关键原则

### 1. 渐进式信息加载（三层架构）

```
Layer 1: Frontmatter（name + description）  ← 始终在上下文中
Layer 2: SKILL.md body（≤400 行）            ← 触发时加载
Layer 3: references/（无限制）               ← 按需加载
```

- SKILL.md 超过 400 行时，把详细内容移到 references/
- 在 SKILL.md 中明确写"详细内容见 references/xxx.md"

### 2. 先做什么后做什么

AI 最怕"先读 references/xxx.md"这种指令出现在流程中间。
应该把主流程写在 SKILL.md 里，references 只在需要时才读取。

**❌ 错误写法：**
```
## 步骤
1. 读取 references/xxx.md
2. 读取 references/yyy.md
3. 执行分析
```

**✅ 正确写法：**
```
## 步骤
1. 收集输入
2. 执行分析（如需参考模板，见 references/xxx.md）
3. 生成输出
```

### 3. 表格优于段落

AI 读表格比读段落快得多，且不容易遗漏。

**❌ 错误写法：**
```
当客户说太贵了，应该先确认他的预算范围，然后提供TCO分析，
如果他是美国客户就用ROI话术，如果是德国客户就给技术数据...
```

**✅ 正确写法：**
```
| 客户反应 | 推荐策略 | 见 |
|---------|---------|-----|
| "太贵了" | 确认预算 → TCO 分析 | objection-library.md A01 |
| "已有供应商" | 不攻击竞品 → 强调原厂优势 | objection-library.md A02 |
```

### 4. 代码块优于文字描述输出格式

AI 看到代码块会直接复制结构，看到文字描述会自由发挥。

**❌ 错误：** "输出一个包含公司名、行业、评分的报告"
**✅ 正确：** 用代码块展示完整输出模板

### 5. 规则要解释 Why

**❌ 禁止在开发信中包含价格**
**✅ 开发信中禁止包含具体金额（$、¥、€），因为 AI 会幻觉价格，一旦客户记住了错误低价，后续无法修正**

### 6. 每个技能都要有踩坑记录

过去犯过的错 + 修复方案，让 AI 不重蹈覆辙。

## 四、Frontmatter 规范

### 必填字段

```yaml
---
name: skill-name          # 必填，kebab-case
version: 1.0.0           # 必填，语义化版本
description: "..."       # 必填，50-150 词，包含触发关键词
triggers:                # 必填，3-10 个触发词
  - 关键词1
---
```

### description 写法

- **包含做什么**：核心功能
- **包含何时触发**：使用场景
- **包含关键词**：用户可能说的话
- **稍微"强势"一点**：AI 倾向于不触发技能

**❌ 弱触发：** "客户背调技能，用于调研公司背景"
**✅ 强触发：** "客户背调技能 — 输入公司名自动搜集公开信息输出结构化报告。当用户提到'背调'、'调研公司'、'查一下这家公司'、'company research'时使用，即使只是简单查询也应触发以提供专业级输出"

### triggers 写法

- 包含中英文关键词
- 包含用户可能说的口语化表达
- 包含缩写和变体

```yaml
triggers:
  - 客户背调
  - 调研公司
  - company research
  - 查一下这家
  - background check
```

## 五、Quick Reference Card（放在流程之后）

每个技能都应该有一个快速参考卡，让 AI 不用读完全文就能行动。

```markdown
## 快速参考

| 你要做的 | 执行 |
|---------|------|
| 背调公司 X | 执行三轮搜索 → 输出 6+6 报告 → 保存到 NAS |
| 客户说"太贵" | 查 objection-library.md A01 → 选择策略 → 生成回复 |
```

## 六、版本管理

- 每次修改 SKILL.md 都更新 `version`
- 在底部维护变更记录
- 重大重构更新 minor 版本（1.0 → 1.1）
- 小修小补更新 patch 版本（1.1.0 → 1.1.1）

---

## 七、检查清单

新建或修改技能时，逐项检查：

- [ ] Frontmatter 四个字段齐全（name/version/description/triggers）
- [ ] description 包含触发关键词且够"强势"
- [ ] 有"何时使用/何时不使用"章节
- [ ] 核心流程用流程图或编号步骤（不用大段文字）
- [ ] 有 Quick Reference Card
- [ ] 输出格式用代码块模板（不用文字描述）
- [ ] 规则解释了 Why（不只是说"必须"）
- [ ] SKILL.md ≤ 400 行（超出部分移到 references/）
- [ ] references/ 文件有明确的"何时读取"指引
- [ ] 有踩坑记录（版本历史/已知问题）
- [ ] 底部有版本号和更新日期
