# 孚盟真实案例存放规范

> 此目录存放从孚盟 CRM 导出的真实成交/失败案例，使用 01-case-template.md 拆解后的结构化数据。

## 文件命名

```
cases/
├── win/                          ← 成交案例
│   ├── W-001-[客户简称].md       ← 化名脱敏，如 W-001-华东化工.md
│   ├── W-002-[客户简称].md
│   └── ...
├── loss/                         ← 失败案例
│   ├── L-001-[客户简称].md
│   └── ...
├── pending/                      ← 待拆解的原始数据
│   └── raw-export.md             ← 从孚盟导出的原始聊天记录
└── README.md                     ← 本文件
```

## 脱敏要求

案例中以下信息**必须脱敏**：

| 原始信息 | 替换为 | 原因 |
|---------|--------|------|
| 客户真实公司名 | 行业+区域代号（如"华东某化工"） | 保护客户隐私 |
| 客户真实姓名 | 姓氏+角色（如"王工""李总"） | 保留角色信息 |
| 真实手机号/邮箱 | 删除 | 不需要存 |
| 精确金额 | 保留（Agent 需要理解量级） | 金额是判断依据 |
| 业务员真实姓名 | 代号（如 Z3） | 保留排名信息 |

**保留不脱敏的：** 产品型号、行业、成交周期、沟通内容原话、决策逻辑。这些是规则提炼的核心数据。

## 案例质量标准

| 指标 | 最低要求 | 理想状态 |
|------|---------|---------|
| 成交案例数 | 5 个 | 20+ |
| 失败案例数 | 2 个 | 10+ |
| 时间线节点数/案例 | 3 个 | 5-10 个 |
| 关键决策点/案例 | 1 个 | 2-3 个 |
| 提炼规则/案例 | 1 条 | 3-5 条 |

## 数据来源

- CRM 系统：孚盟 MX
- 筛选标准：按成交金额降序，取 Top 业务员的案例
- 导出方式：孚盟聊天记录导出 + 邮件记录导出

## 与知识库的关系

```
cases/ (真实数据)
  ↓ 拆解 + 分析
knowledge/ (方法论规则)
  ↓ 验证 + 修正
SKILL.md (可执行决策引擎)
```

案例是规则的**来源和验证基准**。每条规则必须标注来自哪些案例。
