# 影响力 6 大原理：Agent 说服策略库

> 来源：《影响力》罗伯特·西奥迪尼
> 用途：为 Agent 提供客户心理状态识别和说服策略推荐

---

## 六大原理速查

| 原理 | 一句话 | 销售场景触发 | Agent 推荐策略 |
|------|--------|-------------|---------------|
| 互惠 | 先给再取 | 客户觉得你"只想要我买" | 先提供免费价值（案例/报告/试用） |
| 承诺一致 | 人会坚持自己说过的话 | 客户之前承认了需求但犹豫了 | 引用客户自己说过的话推进决策 |
| 社会认同 | 人看别人怎么做自己就怎么做 | 客户不确定要不要买 | 展示同行业客户的使用案例 |
| 喜好 | 人更容易被喜欢的人说服 | 客户对业务员有距离感 | 找共同点、真诚赞美、模仿沟通风格 |
| 权威 | 人服从专家的意见 | 客户质疑产品/方案 | 引用权威数据、标准认证、专家背书 |
| 稀缺 | 越少越想要 | 客户在犹豫不决策 | 提示稀缺性（限量/限时/产能排期） |

---

## 互惠原理（Reciprocity）

### Agent 识别信号
```
IF 客户处于以下状态：
  - 刚开始接触，还不信任业务员
  - 一直处于"你问我答"模式，不主动分享信息
  - 对每次沟通都显得被动
THEN 应用互惠策略
```

### 推荐行动

| 行动 | 示例 | 适用阶段 |
|------|------|---------|
| 送行业报告 | "王工，正好我们整理了一份 XX 行业设备选型白皮书，发您参考" | 线索触达 |
| 送同行案例 | "我之前服务过一家和您类似的化工厂，他们的设备选型过程我整理了个总结" | 需求挖掘 |
| 送检测服务 | "要不我先安排工程师去您现场做个免费检测，看看现有设备的状态？" | 方案对接 |
| 先帮忙后谈生意 | 客户问了一个技术问题 → 认真回答 → 不趁机推销 | 任何阶段 |

### 编码规则
```
RULE: 首次深度沟通前，业务员必须先提供一次无条件的价值
CHECK: 最近 3 次沟通中，业务员有没有提供过对客户有用但不涉及卖东西的信息
```

## 承诺一致原理（Commitment & Consistency）

### Agent 识别信号
```
IF 客户曾经表达过以下任一：
  - "我们确实需要换设备"（承认了需求）
  - "环保整改必须在 X 月前完成"（承认了时间线）
  - "预算大概 XX 万"（承认了预算范围）
  - "你们的技术看起来不错"（认可了某个方面）
BUT 现在开始犹豫或拖延
THEN 应用承诺一致策略
```

### 推荐行动

| 场景 | 策略 | 话术参考 |
|------|------|---------|
| 客户说"再考虑考虑" | 引用他之前说过的话 | "王工，您之前说环保整改必须在 6 月底前完成，现在时间还来得及，要不我们先把方案敲定？" |
| 客户说"价格太贵" | 回到他的需求本身 | "您之前提到产能不够导致每月损失 X 万，这个方案虽然投入 Y 万，但半年就能回本" |
| 客户说"再看看" | 用小承诺推进 | "要不这样，您先安排我们工程师去看一下现场？看完之后再决定也不迟" |

### 编码规则
```
RULE: 每次客户做出正面表态时，记录为"客户承诺点"
RULE: 客户犹豫时，首先回顾"客户承诺点"列表，选择最相关的一个作为推进依据
```

## 社会认同原理（Social Proof）

### Agent 识别信号
```
IF 客户处于以下状态：
  - 说了"我再看看""别人家用什么"
  - 在对比多个供应商
  - 决策链中有"需要说服其他人"的情况
THEN 应用社会认同策略
```

### 推荐行动

| 行动 | 示例 |
|------|------|
| 同行业案例 | "和您同在 XX 工业园的 YY 化工，去年上的就是这套配置" |
| 数据背书 | "我们在这个行业已经服务了 200+ 家企业，返修率低于 1%" |
| 可验证的推荐 | "要不我给您 YY 化工王工的联系方式？您可以直接问他使用体验" |
| 行业标杆 | "XX 集团（行业头部）的 XX 车间也是用这个型号" |

### 编码规则
```
RULE: 方案推荐时，必须附带至少 1 个同行业/同规模客户的案例
RULE: 案例必须可验证（有具体公司名或可以安排参观）
RULE: 优先展示和客户"最近"的案例（同省/同园区/同行业）
```

## 喜好原理（Liking）

### Agent 识别信号
```
IF 客户与业务员的关系处于以下状态：
  - 沟通频率低，客户不主动
  - 对话仅限于公事，没有闲聊
  - 客户态度礼貌但有距离感
THEN 应用喜好原理，但注意分寸
```

### 推荐行动

| 策略 | 方法 | 注意事项 |
|------|------|---------|
| 找共同点 | 同乡、校友、行业经历 | 不要生硬，自然带出 |
| 真诚赞美 | "王工您对设备确实很了解" | 具体不笼统，说事实不说空话 |
| 模仿风格 | 客户用微信就用微信，客户正式就用邮件 | 匹配客户的沟通节奏和用语 |
| 记住细节 | 上次提到的孩子考试/出差/项目进度 | 下次沟通时自然提到 |

### 编码规则
```
RULE: 业务员应该在沟通中记录客户的个人信息（生日/爱好/家庭/关注点）
RULE: 每次沟通开场时，先聊 1-2 分钟非业务话题
RULE: 客户的朋友圈/社交媒体动态是"记住细节"的重要来源
```

## 权威原理（Authority）

### Agent 识别信号
```
IF 客户表现出以下任一：
  - 质疑产品参数/性能
  - 说"你们这个靠谱吗"
  - 要求提供认证/检测报告
  - 决策人（老板/技术总监）在场
THEN 应用权威策略
```

### 推荐行动

| 策略 | 示例 |
|------|------|
| 认证和标准 | "我们的设备通过了 ISO9001 和 CE 认证，检测报告我可以发给您" |
| 数据说话 | "这是第三方实验室的噪音测试数据，比国标低 15 分贝" |
| 专家背书 | "我们的技术总监在 XX 行业有 20 年经验，我可以安排他和您交流" |
| 行业标准引用 | "按照最新的 XX 行业标准，要求达到 YY 指标，我们的设备超标 XX%" |

### 编码规则
```
RULE: 报价/方案中必须包含权威数据支撑（认证/检测/标准）
RULE: 面对技术型客户，优先用数据和标准说服，不用"我们很好"这类空话
RULE: 准备好"可出示的证据"清单：认证、检测报告、客户评价、行业数据
```

## 稀缺原理（Scarcity）

### Agent 识别信号
```
IF 客户处于以下状态：
  - 一直在比较和犹豫，没有明确的决策时间线
  - 说"不着急""慢慢来"
  - 已经认可方案但迟迟不签约
THEN 应用稀缺策略（注意：必须真实，不能编造）
```

### 推荐行动

| 策略 | 示例 | 真实性要求 |
|------|------|-----------|
| 产能排期 | "我们 Q3 的排期已经满了，如果这个月定下来，还能排进 Q2" | 排期必须真实 |
| 优惠期限 | "这个促销价到月底就恢复了" | 必须有真实政策 |
| 库存/型号 | "这个配置的电机目前库存只剩 2 套" | 必须是事实 |
| 竞争压力 | "XX 区域我只设了 1 家代理商，如果您的同行也来问我就不好办了" | 取决于商业政策 |

### 编码规则
```
RULE: 稀缺信息必须真实，永远不编造稀缺性
RULE: 稀缺策略在"客户已认可方案但拖延决策"时使用效果最佳
RULE: 不要在早期使用稀缺策略（客户会觉得是销售套路）
```

## 组合策略（多原理联动）

| 客户状态 | 推荐组合 | 执行顺序 |
|---------|---------|---------|
| 新客户，第一次沟通 | 互惠 + 喜好 | 先建立好感 → 提供免费价值 |
| 客户认可需求但犹豫 | 承诺一致 + 社会认同 | 回忆他的承诺 → 展示同行案例 |
| 技术型客户质疑 | 权威 + 社会认同 | 出示数据/认证 → 同行案例佐证 |
| 客户拖延不决策 | 承诺一致 + 稀缺 | 回忆时间线承诺 → 提示真实稀缺性 |
| 价格谈判中 | 承诺一致 + 互惠 | 回忆他说过的预算 → 用增值服务替代降价 |

## 与孚盟数据的交叉验证清单

拆完案例后检查：

- [ ] 销冠是否在使用互惠策略（先给价值再谈业务）
- [ ] 销冠是否在利用客户的"承诺点"推进决策
- [ ] 销冠在客户犹豫时是否用了社会认同（同行案例）
- [ ] 工业设备行业最常用的原理是哪 2-3 个（推测：权威 + 社会认同 + 承诺一致）
- [ ] 哪些原理在工业品 B2B 场景不太适用（推测：喜好原理在正式采购流程中权重较低）
