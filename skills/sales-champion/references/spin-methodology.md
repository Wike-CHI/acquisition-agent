# SPIN 销售法：Agent 可执行规则模板

> 来源：《SPIN Selling》尼尔·雷克汉姆，基于 35000+ 销售案例研究
> 用途：将 SPIN 方法论编码为 Agent 的客户需求判断和提问策略逻辑

---

## 核心原理

SPIN 不是销售话术，是**提问的顺序**。销冠和普通业务员的差距不在答案，在问的问题。

```
S → Situation（现状问题）    了解客户在做什么
P → Problem（难点问题）      找到客户的痛
I → Implication（暗示问题）  把痛放大，让客户自己意识到严重性
N → Need-Payoff（需求-效益问题） 让客户自己说出解决方案的价值
```

**关键原则：顺序不能乱。** 跳过 P 直接推产品 = 新手最常犯的错。

---

## 阶段 1：Situation 现状问题

### Agent 作用
判断客户信息是否充分，如果不充分，推荐业务员应该问什么。

### 判断逻辑

```
IF 业务员尚未了解以下任一信息：
  - 客户当前使用什么设备/方案
  - 设备使用年限
  - 客户公司规模和行业
  - 客户的角色（采购/技术/老板）
  - 采购时间要求
THEN 触发 Situation 阶段
```

### 推荐提问库

| 场景 | 推荐提问 | 目的 |
|------|---------|------|
| 首次接触 | "您现在用的是哪个品牌的设备？用了几年了？" | 了解现状基线 |
| 客户主动询价 | "方便问一下，这个是新项目还是换旧设备？" | 区分需求类型 |
| 客户说"了解一下" | "您是负责选型的还是帮领导收集信息的？" | 确认决策角色 |
| 客户问某个型号 | "您是怎么了解到这个型号的？是在对比几款吗？" | 判断客户调研深度 |

### 注意事项

```
⚠️ Situation 问题不要超过 3-4 个
问太多 = 客户会觉得在审讯
目标：快速摸清 4 个关键信息就够 → 设备现状、公司规模、角色、时间线
```

---

## 阶段 2：Problem 难点问题

### Agent 作用
从客户描述中发现"不满意的地方"，推荐深挖方向。

### 判断逻辑

```
IF 客户在沟通中出现以下信号（任一）：
  - 描述了某个问题（"噪音太大""效率不够""经常坏"）
  - 表达了不满（"还行吧""凑合用"）
  - 提到了新的需求（"想提升产能""要过环保检查"）
  - 对比了竞品（"别人家的怎么样"）
THEN 触发 Problem 阶段
```

### 信号识别词典

| 客户原话模式 | 真实含义 | 追问方向 |
|-------------|---------|---------|
| "还行吧" | 有不满意的地方但没主动说 | "哪个方面觉得不够理想？" |
| "就是有时候会..." | 存在间歇性问题 | "大概多久出现一次？对生产影响大吗？" |
| "想看看有没有更好的" | 对现状不满意 | "现在的方案主要是哪里让您觉得不够好？" |
| "要过环保/安检" | 合规压力 = 强需求 | "这个必须在什么时间前解决？" |
| "产量跟不上" | 产能瓶颈 = 可量化价值 | "目前差多少？如果解决了值多少钱？" |

### 推荐提问库

| 场景 | 推荐提问 | 目的 |
|------|---------|------|
| 客户描述了问题 | "这个问题对您生产影响有多大？比如每月损失大概多少？" | 量化问题的严重性 |
| 客户说"凑合用" | "如果这个问题一直存在，会对您的工作造成什么困扰？" | 把隐性问题显性化 |
| 客户提到多个问题 | "这些问题里，哪个是您最想先解决的？" | 确定优先级 |
| 客户没主动说问题 | "您现在的设备运行中有没有遇到什么不方便的地方？" | 引导客户发现痛 |

## 阶段 3：Implication 暗示问题

### Agent 作用
这是**最关键**的阶段。帮业务员把客户的"小问题"放大为"必须解决的问题"。

### 判断逻辑

```
IF 客户已经承认了问题，但：
  - 还在犹豫要不要解决
  - 觉得"问题没那么严重"
  - 在等预算/等领导决定
THEN 触发 Implication 阶段
```

### 核心策略：连锁推导

```
客户说的问题
    ↓ "这个问题会导致..."
  对生产的直接影响（停机、次品率、产能下降）
    ↓ "进而会导致..."
  对成本的影响（维修费、加班费、原料浪费）
    ↓ "如果一直这样..."
  对业务的影响（交期延误、客户投诉、丢失订单）
    ↓ "甚至可能..."
  对战略的影响（环保罚款、安全事故、竞争力下降）
```

### 推荐提问库

| 场景 | 推荐提问 | 目的 |
|------|---------|------|
| 设备故障问题 | "每次停机大概要多久？这期间产线是完全停还是降产？" | 量化故障的连锁影响 |
| 产能不足 | "产量不够的话，是有订单接不了，还是要加班来补？" | 把产能问题转化为经济成本 |
| 环保问题 | "如果环保检查没过，是罚款还是停工整改？之前有同行遇到过吗？" | 激活合规风险意识 |
| 客户说"不着急" | "如果不尽快处理，到 XX 季节/生产高峰会不会更麻烦？" | 制造时间紧迫感 |

### 典型对话模式

```
❌ 销售直说：您这个问题很严重，应该马上换设备
✅ 暗示问法：您刚才说每月停机 2-3 次，每次停机大概损失多少？如果一年下来这个数字是多少？

区别：让客户自己算出问题有多严重，比你说服他有效 10 倍
```

## 阶段 4：Need-Payoff 需求-效益问题

### Agent 作用
引导客户自己说出"如果解决了这个问题的价值有多大"，而不是业务员去推销。

### 判断逻辑

```
IF 客户已经意识到问题的严重性（Implication 阶段完成），表现为：
  - 开始问"有没有什么办法解决"
  - 主动问产品功能
  - 说"如果能解决 XX 就好了"
THEN 触发 Need-Payoff 阶段
```

### 推荐提问库

| 场景 | 推荐提问 | 目的 |
|------|---------|------|
| 客户意识到问题严重 | "如果这个问题解决了，对您来说最直接的好处是什么？" | 让客户自己定义价值 |
| 客户开始问方案 | "如果有一套方案能把这个损失降到接近零，您觉得值得投入多少？" | 引导客户建立心理价位 |
| 客户犹豫要不要换 | "如果新设备能把产量提升 30% 同时降低故障率，对您部门意味着什么？" | 把价值具象化 |

### 关键原则

```
✅ Need-Payoff 阶段的核心：客户自己说出价值
❌ 绝不能：业务员说"我们的产品能帮你解决 XX"
✅ 而是：业务员问"如果能解决 XX，对您意味着什么？"

原因：客户自己说的价值 → 客户会相信
销售说的价值 → 客户会怀疑
```

## SPIN 阶段转换规则（Agent 核心逻辑）

```
客户首次接触
  → 检查 Situation 信息是否充分
  → 不充分 → 继续问 Situation 问题
  → 充分 → 进入 Problem 阶段

Problem 阶段
  → 客户是否承认了至少一个问题
  → 没有 → 继续挖掘（用信号词典识别隐性问题）
  → 有 → 进入 Implication 阶段

Implication 阶段
  → 客户是否意识到问题的连锁影响
  → 没有 → 继续放大（用连锁推导策略）
  → 有 → 进入 Need-Payoff 阶段

Need-Payoff 阶段
  → 客户是否自己表达了"需要解决方案"
  → 没有 → 继续引导（用价值具象化提问）
  → 有 → 进入方案推荐环节（此时才能介绍产品）
```

### 阶段回退规则

```
客户在报价阶段突然说"我再想想"
  → 不一定是回退，可能是 Implication 不够充分
  → Agent 建议：不催单，用 Implication 提问重新确认客户是否真正意识到问题

客户在方案阶段开始讨论新需求
  → 回退到 Problem 阶段，重新梳理需求
  → 不要直接跳到推荐方案
```

## 量化的 SPIN 效果数据（来源：原书研究）

| 指标 | 新手 | 销冠 |
|------|------|------|
| Situation 提问占比 | 45% | 15% |
| Problem 提问占比 | 20% | 25% |
| Implication 提问占比 | 5% | **35%** |
| Need-Payoff 提问占比 | 5% | **20%** |
| 产品介绍/推销占比 | 25% | 5% |

**核心发现：销冠花 80% 的时间在提问（尤其是 Implication），只有 5% 的时间在推销产品。**

- [ ] 销冠在 Implication 阶段花了多少时间（对比新手）
- [ ] 案例中的"关键决策点"是否对应某个 SPIN 阶段转换
- [ ] 失败案例中，是否跳过了某个阶段（最可能是跳过 Implication 直接报价）
- [ ] 工业设备行业有没有 SPIN 未覆盖的特殊阶段
