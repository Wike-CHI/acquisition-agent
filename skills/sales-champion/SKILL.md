# 销冠决策引擎 v1.0.0

基于三大经典销售方法论，编码为可执行决策规则。帮业务员在关键判断时刻做出销冠级别的选择。

> 规则来源：SPIN Selling（雷克汉姆 35000 案例）、影响力（西奥迪尼）、挑战者销售（Dixon/Adamson）
> 待与孚盟真实成交数据交叉验证后迭代

## 核心决策框架（常驻）

### 1. SPIN 阶段判断

每次与客户沟通时，判断当前阶段：

```
S（现状）→ 客户背景不明 → 问 2-3 个问题摸底（不审讯）
P（难点）→ 发现痛点 → 深挖"哪里不满意"
I（暗示）→ 把痛放大 → 连锁推导：问题→生产影响→成本→业务→战略
N（需求-效益）→ 客户自己说价值 → 此时才能推荐方案

铁律：S→P→I→N 不可跳过。跳过 I 直接推产品 = 新手错误。
```

### 2. 影响力 6 原理速查

| 原理 | 触发 | 行动 |
|------|------|------|
| 互惠 | 信任未建立 | 先给价值再谈业务 |
| 承诺一致 | 客户反悔/犹豫 | 引用他原话 |
| 社会认同 | 客户不确定 | 同行案例（可验证） |
| 喜好 | 有距离感 | 记住细节、找共同点 |
| 权威 | 客户质疑 | 数据/认证/标准 |
| 稀缺 | 拖延不签 | 真实稀缺性（禁止编造） |

### 3. 角色化话术速查

| 角色 | 关心什么 | 怎么说 |
|------|---------|--------|
| 技术工程师 | 参数、可靠性 | 具体数据 + 无故障时间 |
| 采购经理 | 价格、付款、交期 | 配置选项 + 条件交换 |
| 老板/总经理 | ROI、合规风险 | 回本周期 + 风险成本 |
| 生产主管 | 产能、良品率 | 使用数据 + 量化提升 |

### 4. 信号识别词典

| 客户说 | 真实含义 | 你怎么做 |
|--------|---------|---------|
| "把报价发我看看" | 在比价 | 报价但附差异化说明 |
| "领导说再看看" | 我不是决策人 | 问领导关心什么 |
| "你们和XX比怎么样" | 已有竞品方案 | 不贬竞品，说差异化 |
| "价格能再低吗" | 想买/试探底线 | "低到多少您能定？" |
| "不着急慢慢看" | 优先级低 | 降低频率不消失 |
| "帮我出个方案" | 认真考虑中 | 方案体现需求理解 |

## 8 条核心决策规则

```
R01: 客户询价但没说需求 → 先问场景再报价（锁对话）
R02: 客户提竞品更便宜 → 不降价不贬竞品，引导比配置
R03: 客户说"再考虑"且之前正常 → 不催单，发同行案例
R04: 竞品价格低10%+ → 从价格转风险/总拥有成本
R05: 客户说了需求量 → 立即追问决策链
R06: 客户说"太贵" → 区分超预算还是觉得不值
R07: 报价阶段 → 两个方案（标准+高级），锚定效应
R08: 成交后 → 立即提供额外价值，巩固关系
```

## 典型场景应对

### 客户压价
```
区分："您是觉得超预算了，还是觉得不值这个价？"
超预算 → 调配置/付款方式
觉得不值 → 回到价值塑造（Implication）
```

### 客户说"再考虑"
```
找真正顾虑："通常是有某个担忧没说出来，是担心XX？"
不催单 → 用证据替代催促（同行案例/行业信息）
```

### 客户拿竞品比价
```
不贬竞品 → 重新定义比较标准
"建议您关注三个数据：3年维护成本、配件价格、售后响应时间"
```

## 与孚盟数据的验证流程

本技能的规则需要用真实数据验证。验证方法：

1. 从孚盟导出 5 个成交 + 2 个失败案例
2. 拆解案例（参照 `docs/research/sales-champion-extraction/01-case-template.md`）
3. 对照规则看销冠行为是否匹配
4. 匹配 → 保留；不匹配 → 修正规则；缺规则 → 新增

验证通过标准：新案例预测一致率 > 70%
